# Delegate recovery consumer

The packaged bundle pins `tool-delegate` to Foundation revision `52cbf74f99cc16ae88a2043840b253576269c704`. Other Foundation modules, the Python dependency, and Anchors keep the recursive source lock at `dea5bd8fe11a7617dbcfc61c47f9f4f2fdc0b134`. Explicit user module-source overrides remain authoritative.

This module revision consumes the host's `session.partial` capability and forwards `provider_preferences` and `model_role` to `session.resume`. It includes upstream [resume routing #350](https://github.com/microsoft/amplifier-foundation/pull/350), [timeout partial results #353](https://github.com/microsoft/amplifier-foundation/pull/353), and [partial guidance #356](https://github.com/microsoft/amplifier-foundation/pull/356). The packaged `settings.timeout: null` preserves the previous disabled timeout default; users may configure a positive deadline explicitly.

A timed-out result is unsuccessful and carries `partial_response`, never the completed `response` field. The consumer cancels and detaches the child at its deadline. Runtime must retain writer ownership until actual child cleanup finishes and publish partial data before cancellation unwinds. An unavailable partial is reported as unavailable. The consumer accepts a synchronous getter, avoiding disk or context awaits in timeout recovery.

The candidate module was checked against Runtime's Core 1.6.1 and pinned Foundation with 52 upstream timeout, partial-result, and resume-routing tests. A separate offline probe exercised the module's public mount and execute functions with controlled host callbacks and observed partial output plus cancellation cleanup. Those checks establish consumer compatibility; full Runtime lifecycle and client acceptance remain separate requirements. The upstream timeout-marker plugin was absent, producing five marker warnings; the tests' asyncio deadlines executed.

An opt-in Runtime integration test loads the immutable consumer with `AMPLIFIER_DELEGATE_SOURCE` pointing to a Foundation checkout. It uses actual SessionSpawner capabilities and session storage with controlled provider execution to verify timeout partials, refusal to resume before cleanup releases ownership, and faithful continuation through a fresh spawner. The test verifies the checkout revision and skips when the source path is absent; it performs no network fetch.
