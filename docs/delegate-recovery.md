# Durable delegated sessions

Runtime-backed sessions register `session.spawn`, `session.resume`, and `session.partial`. The packaged delegate tool is pinned separately from Foundation so its timeout handler consumes partial output. Other custom tools must support these capabilities before they can offer recovery. A `SessionSpawner` constructed without a store remains ephemeral and does not advertise resume.

Every child has a private `delegate.v1.json` record in its normal session directory. This versioned record atomically stores the resolved configuration, agent instruction, parent and project identities, balanced model messages, an execution identity, and the last recorded outcome. Bounded in-flight diagnostics live separately in `delegate-partial.v1.json`, keyed to that execution; stale or corrupt diagnostics cannot replace the safe checkpoint. Existing transcript/metadata files are history projections; they are not the authority for delegate resume. Existing ephemeral children have no record and must be delegated again.

A checkpoint is written before execution and at provider-request boundaries only when tool calls and results are balanced. Completed text blocks and tool activity update bounded partial diagnostics during normal execution, without inserting unfinished content into the model checkpoint or rewriting the full transcript for every block. A resumed child receives a logged warning that external tools may have executed after the checkpoint and that actual state must be inspected before repeating side effects. Recovery does not guarantee exactly-once external execution.

The execution lock covers initialization, execution, and cleanup. A second owner fails immediately; a process crash releases the OS lock. A last-recorded `in_progress` checkpoint whose owner is gone reads as incomplete. Task cancellation does not await context retrieval or write a rescue checkpoint; recoverable work was persisted before the timeout. Cleanup may still run after the delegate tool reports a timeout, and resume remains unavailable until it releases ownership. Core cooperative cancellation can return normally; its cancellation event still marks the child incomplete and prevents an automatic builder retry or successful completion record.

Resume must be requested through the original parent. The same child ID cannot be spawned again, and root-session resume rejects delegated records. The resolved provider model, endpoint, effort, and priority are preserved; only sensitive provider fields are refreshed from the matching live provider identity/source. Missing or replaced providers fail explicitly. Saved tool, hook, context, and orchestrator sources are checked against the live composition; child-only modules require immutable Git sources for resume. New and resumed durable children use an isolated resolver cache, so an earlier child cannot silently replace their modules. Source-free installed overlays can start, but child-only overlays without immutable sources cannot resume. Unknown resolvers and missing source resolution fail explicitly. Equivalent cached routing arguments are accepted, but changing routing during resume is rejected; start a new delegate for a new routing decision. Live parent governance and cancellation remain attached to resumed children.

The synchronous `session.partial` callback returns bounded already-published diagnostics for the tool's timeout response; it never waits for cancellation cleanup. Persisted diagnostics remain available through `DelegateStore.load` after a process restart. TUI and Studio use the normalized completion's incomplete flag and result summary to show retained work. A completion or timeout does not imply that a checkpoint contains every last tool result.

Storage uses existing private-file modes and shared credential redaction. Child records live with the session store and follow its retention/deletion policy. Do not downgrade to a build that would open these children as ordinary root sessions; keep older application artifacts for inspection while using a compatible Runtime to access delegate records.

## Verification

`tests/test_delegate_recovery.py` covers first-request interruption, partial publication before cancellation, balanced tool history, identity/ownership, provider secret rotation, and terminal errors. `tests/test_delegate_consumer_integration.py` is an opt-in offline integration with the exact upstream module source: set `AMPLIFIER_DELEGATE_SOURCE` to the Foundation checkout root at the immutable revision specified by that test. It exercises the public tool entry point against Runtime's actual spawner, store, and lock, including deferred cleanup and fresh-spawner continuation. Tests without that source skip the optional consumer check; they do not claim to verify the installed delegate tool.

`tests/test_runtime_offline.py` also exercises registered spawn/resume callbacks through actual Core session creation and module initialization. `tests/test_delegate_partial_storage.py` verifies bounded diagnostic writes leave the transcript and checkpoint unchanged and cannot leak across execution identities. These offline checks use controlled providers; they are not real-provider acceptance.
